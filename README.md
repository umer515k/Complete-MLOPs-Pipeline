## Overview

This project demonstrates a full MLOps workflow built from the ground up. It goes beyond model training — it wraps the model in a production API, containerizes it, provisions cloud infrastructure as code, and automates the entire deployment process through CI/CD.

**What makes this production-grade:**
- Every push to `main` triggers automated testing, Docker image builds, and zero-touch deployment
- Infrastructure is fully reproducible via Terraform — no clicking around the AWS console
- Every Docker image is tagged with the exact git commit SHA, making every deployment traceable
- Deployments only happen after tests pass — broken code never reaches the server

## Architecture

```
Developer Machine
      │
      │  git push
      ▼
GitHub Repository
      │
      ▼
GitHub Actions CI/CD
      │
      ├── Job 1: Test
      │     ├── Train model
      │     └── Run pytest suite
      │
      ├── Job 2: Build & Push  (only if tests pass)
      │     ├── Build Docker image
      │     └── Push to Docker Hub (tagged with commit SHA + latest)
      │
      └── Job 3: Deploy  (only on main branch)
            ├── SSH into EC2
            ├── Pull latest image
            └── Restart container
                    │
                    ▼
          AWS EC2 (t2.micro)
          ├── /health
          ├── /predict
          └── /docs (Swagger UI)
```

## Getting Started

### Prerequisites

- Python 3.11+
- Docker
- Terraform
- AWS CLI + account
- Git

### Local Setup

```bash
# Clone the repo
git clone https://github.com/umer515k/Complete-MLOPs-Pipeline.git
cd Complete-MLOPs-Pipeline

# Create and activate virtual environment
python3 -m venv venv
source venv/bin/activate

# Install dependencies
pip install scikit-learn fastapi uvicorn pydantic pytest httpx

# Train the model
python training/train.py

# Start the API
uvicorn app.main:app --reload
```

API is now live at `http://localhost:8000`
Interactive docs at `http://localhost:8000/docs`

### Docker

```bash
# Build image
docker build -t mlops-pipeline:v1 .

# Run container
docker run -p 8000:8000 mlops-pipeline:v1
```

## CI/CD Pipeline

The pipeline is defined in `.github/workflows/ci.yml` and runs on every push to `main` and every pull request.

### Jobs

**1. Test**
- Sets up Python 3.11
- Trains the model from scratch
- Runs the full pytest suite

**2. Build & Push** *(requires Test to pass)*
- Builds the Docker image
- Pushes to Docker Hub with two tags:
  - `latest`
  - `<commit-sha>` (every image is traceable to an exact commit)

**3. Deploy** *(requires Build to pass, main branch only)*
- SSHs into the EC2 server
- Pulls the latest image
- Stops and removes the old container
- Starts the new one with `--restart unless-stopped`
- Prunes old images to save disk space

PRs trigger Test and Build but **never Deploy** — only merges to `main` ship to production.

### Required GitHub Secrets

| Secret | Description |
|---|---|
| `EC2_HOST` | Public IP of your EC2 instance |
| `EC2_USER` | SSH username (`ec2-user` for Amazon Linux) |
| `EC2_SSH_KEY` | Private SSH key (base64 encoded) |
| `DOCKERHUB_USERNAME` | Docker Hub username |
| `DOCKERHUB_TOKEN` | Docker Hub access token |

## Infrastructure

Infrastructure is managed with Terraform. Everything is reproducible — one command spins up the full environment.

```bash
cd terraform
terraform init
terraform plan
terraform apply
```

### What gets provisioned

- **EC2 instance** — `t2.micro` (AWS free tier), Amazon Linux 2
- **Security group** — ports 22 (SSH) and 8000 (API) open
- **Key pair** — SSH key uploaded to AWS for passwordless auth
- **Docker** — installed automatically via `user_data` startup script

### Tear down

```bash
terraform destroy
```

Wipes all provisioned resources cleanly. No surprise AWS bills.

## API Reference

### `GET /health`

Health check endpoint.

```bash
curl http://<server-ip>:8000/health
```

```json
{"status": "ok"}
```

### `POST /predict`

Run sentiment prediction on a piece of text.

```bash
curl -X POST http://<server-ip>:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "This product is absolutely amazing"}'
```

```json
{
  "text": "This product is absolutely amazing",
  "sentiment": "positive",
  "confidence": 0.923
}
```

### `GET /docs`

Interactive Swagger UI — test the API directly in your browser.
